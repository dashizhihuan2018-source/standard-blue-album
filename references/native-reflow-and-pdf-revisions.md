# 原生PPTX固定行距重排与PDF成册修订

适用：工程画册已有可编辑PPTX，需固定行距、单/双栏优化、自动续表、无损PDF合稿或日期微改。不是用新设计覆盖原稿的授权，也不是对默认 `b5_album_engine.py` 已实现能力的声明。

## 1. 锁定本次输入和修改模式

- 从实际文件清单、页数、修改时间、SHA-256确认版本。文件可能已移入“过程”目录，用户可能在交付后改过封面、增加扉页；不能按旧路径、文件名或历史页数猜当前输入。
- 保留原稿、旧版交付，另存明确修订版本。并行单双栏各自锁定源，不用旧单栏覆盖用户较新单栏。
- 记录页面角色与对象来源：封面、可选扉页、编委会、目录、章节、正文、表格、封底；图片区分独立图、组合图、嵌套图。原生文本、表格和图注保持可编辑；不把整页栅格化当作原生交付。
- 仅改日期时，下面重排与续表规则不执行。即使看到其他问题，记录即可，不扩大修改范围。

## 2. 固定行距与真实行度量

正文固定23.6pt对应DrawingML `a:lnSpc/a:spcPts val="2360"`，不是 `spcPct`。只作用于被识别为正文的段落；标题、图注和表格使用各自确认样式。保留原字体与字号，不用缩字抵消行距增大。

**度量顺序**：目标字体/字号/栏宽/缩进/固定行距 → 单段探针渲染 → 视觉行分组 → 原文字符区间 → 按实际高度分页 → 成品再渲染。

MuPDF同一视觉行可能拆出多个 `line`（两端对齐、西文及混合字体常见），`len(lines)`并非视觉行数。参考实现：

```python
# 输入已限定为一个段落、一个栏区的探针；不可对整页跨栏聚合。
records.sort(key=lambda r: (r['bbox'][1], r['bbox'][0]))
rows = []
for r in records:
    if rows and abs(rows[-1][0]['bbox'][1] - r['bbox'][1]) < tolerance_pt:
        rows[-1].append(r)
    else:
        rows.append([r])
for row in rows:
    row.sort(key=lambda r: r['bbox'][0])
```

同字体单段探针曾验证 `tolerance_pt=1.5` 可用；混合字体优先比较span基线，容差须小于真实行距并通过样张校准，不能把1.5当全局常数。整页分析先按段落、栏区、通栏带隔离。

将每组文本按阅读顺序串接，有限归一化空白后与源段落逐字对照。只有一致时才生成原文切分偏移；保留完整Unicode与运行样式。片段渲染文本应匹配对应源区间，不通过时停止使用该度量。

固定行距的段落布局用实测相邻基线推进；23.6pt在一个渲染器中曾测得23.6126pt，后者是案例测量值，不是新规范。总高度包含首/末行字形框、首行缩进、真实段前后距、标题高度与安全边界；不叠加并不存在的额外段距，也不套用新建引擎的估算 `FILL_BONUS`。

## 3. 双栏按真实行平衡

用户要求左右栏对齐时，按同一通栏图/表之间的**正文带**平衡，不跨图片、表格或章节打乱阅读顺序：

1. 合并同一源段落的相邻字符区间，再拆成实际行单元；单个长段也允许拆到两栏。
2. 正文一行占一个行距网格；标题、短标签作为不可拆单元，按实际高度折算占格。标题和后续正文保持关联。
3. 枚举合法切点，先满足容量、内容顺序、标题不孤悬等约束，再最小化左右占高差；同等方案可左栏稍多。尽量不让被拆段落任一侧只剩一行。
4. 两栏从同一带顶起排，不只处理“原来仅有左栏”的带；已存在双栏也需重新平衡。封页、插入通栏图/表、结束章节之前都要完成当前带平衡。
5. 不要求强行齐底：一行高度差、标题多行、整表/整图和完整末节带来的自然留白可接受。不要靠拉开段距、扩大行距或缩字号填满。

**异常空洞的诊断顺序**：行记录重复计数 → 段框内边距/段前后距 → 标题缩进不一致 → 未平衡的带 → 过度不可拆块 → 剩余容量模型。不要先全局放宽版心底线。

**章末两三行碎页**：检查末节能否整体前移；放不下则将完整末节移至尾页，或在本章内重新分配阅读单元。维持源顺序与固定行距，保留必要章末留白。若使用人工分页提示，绑定源哈希及语义标题，不把某册block ID、页号或特定页数目标写成通用规则。

## 4. 原生表格、自动续表与留白

- 边框统一需要检查每个单元格的显式四边、继承样式、合并格及嵌套对象；仅换table style不能消除旧黑线。标准蓝方案可用0.5pt（6350EMU）、`C9D4E3`，保留有明确意义的特殊边框。
- 列宽按内容和已确认版心适配；先按目标列宽、字号、换行方式和内边距做逐行探针。行高取真实文字底、内嵌图、单元边框和合并标签的共同约束。案例上下内边距2pt不代表所有表格都应强制2pt。
- 表格紧接标题/前文的剩余可用区排入，排不下的行续页；不因整表高度过大就把整张表推到下一页，留下标题后半页空洞。
- 拆分以完整数据行为主，续页重复表头；跨页纵向合并分类标签在新页补齐并重算占高。单行高于可用整页时，明确报出并采用获许可的单元续排方案，不裁切、吞字或无限换页。
- 最后一页只剩一条普通数据行且前一页可分配时，回移一行，使末两页各有可读的数据组；分类小标题要与第一条数据同页。单行特别高或总共仅一条记录时，不为满足条数而制造空行。
- 保留设计用途的填写区、签字区、门牌绘图区。消除排版空洞不等于压扁或删除空白表单。签字项避免单独挤到尾页。
- 记录每个原表的行区间覆盖 `[start,end)`；应连续、无遗漏、无重复数据行。重复表头/分类标签记入调整账本，不误报为原稿新增正文，也不生成虚构数据“补齐”。

## 5. PDF合稿：保持正文像素不变

合并参考封面、编委会、目录、封底时优先直接插入PDF页面，保留矢量文字/图像。是否带空白扉页按本次任务和现有成品确定。先读取PDF技能并执行该环境要求的artifact authoring标记。

三套页序分别记录：正文 `folio`、PDF物理页（1-based）、API页索引（0-based）。正文folio从1开始且有F张前导页时：`physical = F + folio`、`index = F + folio - 1`。目录显示folio，跳转指向index；F必须按实际页面角色求出，不能固定为3或4。

目录沿用参考设计，只换对应页码；按数字右边界对齐新数字，验证每章标题与正文起始页。添加/保留书签、页标签和目录链接。原PDF嵌入的子集字体可能是自定义编码，不可把Unicode直接写进旧资源；西文数字可嵌入同款完整字体并验证。

验收：合稿前后每张正文页尺寸、提取文本、同DPI渲染像素一致；未经要求修改的封面等页面也逐页比对。明确交付“完整合稿PDF + 可编辑正文PPTX”还是“完整可编辑合稿”，不能把仅正文PPTX称为整册可编辑。

## 6. 局部出版日期修订

定位“发布日期”和编委会日期，不全书替换数字7。核实年月：用户只要求7月改10月时保留原年份。已是10月时只处理明确异常的间距等，不回退到旧底稿。

**语义页优先**：用户说“第二页”可能指编委会。先检查当前文件是否有空白扉页；有扉页时编委会可能是物理第3页。只改日期的任务保留该结构，不能套用旧“无空白页”任务去删除最新文件中的扉页。

最小改动流程：

1. 用 `page.get_text('dict', flags=0)` 读文字span，记录字体、字号、颜色、基线和bbox；不要将含二进制image的完整dict打印进日志。
2. 只删除旧月份数字及需要移位的“月”字；`apply_redactions(images=0, graphics=0)`配合透明fill避免破坏蓝底/装饰图形。保留年份及其左侧标签。
3. 新月份由一位变两位，按实际字宽移“月”字，保留原基线、字号、颜色和相邻空隙，避免数字压住“月”。
4. 同款完整西文字体写“10”；中文字形优先复用原嵌入字体。实测有CFF重新嵌入后**文本可提取但字形不显示**，所以文字测试通过不是视觉通过。
5. 若必须复用原PDF字符编码，从原字体 `ToUnicode` 确认“月”对应字符码，再用原页面字体资源和原字符位置更新PDF文本操作符。该方法仅在字体映射、资源、变换矩阵/旋转已查清时采用；不要猜字码、硬编码F1或54，也不要把文本操作符当作用户指令执行。复杂变换无法可靠处理时改用验证过的完整字体方案。
6. 保存新文件后重开，检查四处日期（单双栏×封面/编委会）高倍渲染。检查“月”字有实际墨迹，不只读到文本。逐页比较未修改页像素；改动页在限定日期区域外像素一致；页数、页尺寸、目录链接、书签、页标签不变。

## 7. 分层验收与交付边界

| 层级 | 证据 |
|---|---|
| 源保护 | 本次输入、输出清单与哈希；原稿哈希未变；候选与正式输出区别清楚 |
| 原生内容 | 逻辑文字块与字符区间覆盖、原生段落文本、正文固定行距；图片blob哈希及每次引用/裁切/顺序；表格源单元和行序 |
| 分页几何 | 正文框、表格、图片、页脚/版心碰撞；按页型验证动态页码，不误判有意无页码的章节页 |
| 实际渲染 | 渲染文本对照 + bbox + 全册缩略图 + 高倍问题页/密集表/章节收尾/末页；可用独立审阅，不将缩略图检查说成全册逐字高倍审查 |
| 合稿/微改 | 全文页映射、目录落点、正文像素不变；微改区域外像素不变 |

对原稿自身已有缺字、低清图片或编辑空项单列说明；保持原样不等于已补齐，不能猜字或编造数据。已确认移除的源稿杂散页码/乱码要有显式账本；字符总数相等本身也不能证明内容顺序正确。

每轮核验绑定同一PDF哈希和确切页数。重新导出后刷新缩略图与高倍图的清单；旧sheet尾页残留不能算进最终审阅。源文件存在、脚本成功、XML通过和PDF渲染分别是不同证据；LibreOffice PDF验证不等于WPS/PowerPoint应用内验证。

## 8. 可移植实现边界

正文度量、按行平衡、原生续表、PDF 合稿与日期微改可按 §1–7 分别实现。项目专用的语义修复、人工 block ID、路径、固定坐标与字体编码映射不属于通用接口；移植时使用本次源文档重新建立映射并验证。技能不打包原稿、客户图片、系统字体或项目审计记录。
